# Slice: Goals

**Date:** 2026-06-03
**Status:** Complete

## Description

Delivers the Goals module: the `GoalsListScreen` (F-8) and its four associated dialogs
(`CreateGoalDialog` F-9a, `GoalValueDialog` F-9b, `SelectAccountsDialog` F-10,
`BankAccountAllocationDialog` F-11). Also implements the Goals core and application services
(G-OP-1 through G-OP-6).

F-11b (Goal Allocation View) is explicitly out of scope for this slice and will be addressed
in a follow-on slice. G-OP-7 and G-OP-8 are therefore also deferred.

This slice picks up from the Dashboard stub in `ui/screens/dashboard.py` where
`btn-goals` currently shows "Module not yet implemented."

## Decisions Made

- **U-1 resolved — GoalValue / GoalBankPortion type changes are hard-delete + re-insert.**
  `GoalValue` and `GoalBankPortion` are composition-owned by their parent `Goal`; they have no
  independent lifecycle dates and are not `Discardable`. When G-OP-3 changes the strategy type
  (e.g. Manual → PV) or G-OP-6 toggles AutoFill ↔ Scalar, the service hard-deletes the old
  row and inserts a new one.

- **U-2 resolved — Initial scalar amount on AutoFill → Scalar is $0.**
  When F-11 unchecks "Fill difference", G-OP-6 creates a new `GoalBankPortionScalar` with a
  `$0` initial entry. The user edits the amount inline in F-8 after switching.

- **U-3 resolved — Monthly PMT helper lives on `SimplePVGoalValue` (domain entity).**
  `SimplePVGoalValue.monthly_payment(effective_date: date) → Decimal | None` is added alongside
  `calculate_target`. Formula: PMT = FV × r / ((1 + r)^n − 1) where r = discount_rate/12
  and n = whole months from `effective_date` to `maturity_date`. Returns `None` if any
  required field is None or if n ≤ 0.

- **U-4 resolved — Bank overclaim uses `GoalAppService` calling `BalanceSheetService`.**
  Each UI screen interacts only with its own application service. Application services may fan
  out to any core service. `GoalAppService.get_goals_summary` calls `BalanceSheetService` for
  the BANK balance total to compute the overclaim flag. Technical charter updated
  accordingly.

- **U-5 resolved — AutoFill calculation performs live quote fetches via `BalanceSheetService`.**
  Account balances for allocated `InvestmentAccount`s (including listed security holdings)
  must be fetched through `BalanceSheetService` so that unit prices are injected before
  `get_balance` is called. `GoalService` calls `BalanceSheetService.get_investment_account`
  (or equivalent) to retrieve fully-priced accounts. `None` balance (truly unpriceable account)
  is treated as `$0` per existing domain behaviour.

- **U-6 resolved — Inline Bank Alloc editing in F-8 calls G-OP-6.**
  The `[...]` button is removed from the Bank Alloc column. `F6` (from either editable or
  gold-bordered state) opens `BankAccountAllocationDialog` (F-11). In scalar mode the field
  is editable; `Enter` on a modified value calls G-OP-6 with `fill_difference=False` and
  the new amount. In AutoFill mode the field is gold-bordered and read-only.

- **U-7 resolved — Inline Goal amount editing in F-8 calls G-OP-3.**
  The `[...]` button is removed from the Goal column. `F6` (from either state) opens
  `GoalValueDialog` (F-9b). In Manual mode the field is editable; `Enter` on a modified
  value calls G-OP-3 with the new scalar amount. In PV/NoTarget mode the field is
  gold-bordered and read-only.

- **U-8 resolved — F-3 shows "not yet implemented" notification.**
  Since F-11b is out of scope, `F3` in `GoalsListScreen` shows a "Module not yet implemented"
  notification (same pattern as the Dashboard Goals stub). The binding appears in the footer.

- **`Ins` replaced by `F2` throughout Goals flows.** Consistent with the Balance Sheet and
  Investment Editor convention. Canonical spec updated.

## Late-Session Fixes (2026-06-05)

The following corrections and polish items were applied before closing the slice:

- **Difference column sign corrected.** The column now shows `inv_alloc + bank_alloc − target`
  (positive = surplus, negative = short). Both `GoalAppService.get_goals_summary` and the
  incremental `GoalRow._refresh_difference` method were updated, along with the canonical UI
  spec (F-8) and the `GoalSummaryRow` docstring.

- **`BankAccountAllocationDialog` checkbox replaced with `ToggleRow`.** Textual's built-in
  `Checkbox` was replaced with a new reusable `ToggleRow` widget (in `goal_dialogs.py`)
  that uses the same `Static(RichText("[ ]"))` / `Static(RichText("[x]"))` indicator
  pattern as `AccountListItem` in `SelectAccountsDialog`. Old `Checkbox` CSS rules removed
  from `netware.tcss`; `ToggleRow`-specific rules added. `Checkbox` import dropped from
  `goal_dialogs.py`.

- **Enter toggles accounts in `SelectAccountsDialog`.** `on_key` now handles both `"space"`
  and `"enter"`. Guard added: Enter/Space are only intercepted when the `ListView` itself
  is focused (`self.focused is lv`), so buttons receive Enter unmodified.

- **Blocked accounts skipped during navigation.** `AccountListItem.on_mount` sets
  `self.disabled = True` for accounts assigned to another goal. Textual 8.2.6's
  `ListView.action_cursor_down/up` checks `item.disabled` and skips these items.
  `opacity: 1` override added in `netware.tcss` to prevent any visual dim.

- **Bank allocation non-negative floor.** `GoalBankPortionAutoFill.get_value()` now returns
  `max(Decimal("0"), target − allocated_sum)` — investment overallocation can never produce
  a negative bank claim. `data-requirements.md` updated; new domain-level test added
  (`test_get_value_overallocated_returns_zero`).
