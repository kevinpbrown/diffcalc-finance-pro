# Slice: Cash Flow

**Date:** 2026-06-09
**Status:** Complete

## Description

Delivers the full Cash Flow module (Flows F-12, F-13, F-14, F-15): three coordinated
screens sharing a common 33/67 left-nav / right-content layout, plus an Automated
Contribution modal. Implements CF-OP-1 through CF-OP-10.

This slice also generalizes the 33/67 split layout pattern established in
`GoalAllocationView` (F-11b) into a reusable component used by all three cash flow
screens.

## Decisions Made

- **U-1 resolved — Extract `TwoPaneScreen` base class.** A shared base class in
  `ui/screens/base.py` handles the 33/67 CSS split, title bar, `Tab`/`Shift+Tab` focus
  cycling between panes, and `SplitFooter`. `GoalAllocationView` is refactored to use it;
  all three cash flow screens are built on it.

- **U-2 resolved — `switch_screen` for all intra-module transitions.** The cash flow
  module's three views are flat peers. Left-pane navigation uses `switch_screen`; `Esc`
  from any view switches back to Dashboard (no screen stack within the module).

- **U-3 resolved — RRSP amounts are stored annually, displayed monthly (÷ 12) in F-14.**
  `auto_rrsp_deducted` and `rrsp_matched` are annual figures on `PersonalCashFlowProfile`.
  Net income is the user-entered take-home (bank deposit), which already reflects RRSP
  deductions — RRSP is therefore NOT subtracted again in the monthly-retained calculation.
  F-14 shows full gross→net reconciliation lines: per-person "Less Automated RRSP for
  \<Name\>" (only when `auto_rrsp_deducted > 0`) + a single derived "Less taxes & other"
  remainder line. These are display-only. Spec updated in `cash-flow.md` F-14.
  Invariant added: `rrspMatched > 0` requires `autoRrspDeducted > 0`; captured in
  `data-requirements.md` and `service-operations.md` CF-OP-2.

- **U-4 resolved — `AutomatedContribution.target_goal_id` non-nullable is correct.**
  Automated contributions are investment contributions that always target a goal.
  Non-investment recurring payments (mortgages, insurance) belong as expenses instead.

- **U-5 resolved — `AutomatedContribution.amount` and `HouseholdExpense.amount` are
  both monthly.** `PersonalCashFlowProfile` income fields are annual. This inconsistency
  is acknowledged; a clean-up slice is deferred.

- **U-6 resolved — Account type filtering for F-15 is UI-only.** "From account" shows
  bank accounts; "To account" shows investment accounts. The constraint is a usage
  convention (visibility/reporting only, no functional implications), not a domain
  invariant. Service enforcement deferred pending a decision to add functional implications.
  See `CashFlowAppService.get_bank_account_options` / `get_investment_account_options`.

### Key Conventions Established

- **`_CashFlowNavPane`** renders persons + separator + Expenses + Household Cash Flow via a single `Rich.Text` `render()`. All three sibling screens share it; `on_select` callbacks drive `switch_screen`.
- **Dollar alignment**: `_ReportRow._rr-amount` uses `width: 20; padding: 0 2; content-align: left middle` with fixed 16-char format strings to align the `$` sign with `GoldBorderDisplay` at the same widget position.
- **Vertical centering in 3-row widgets**: Label Statics inside height-3 row widgets must declare `height: 3` explicitly for `content-align: left middle` to centre vertically.
- **RRSP reconciliation**: Gross → RRSP lines → taxes remainder → net. Net income is the bank deposit and is NOT further reduced by RRSP in the "Less:" section.
